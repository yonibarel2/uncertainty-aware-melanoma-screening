# Submission and Presentation Requirements

> Key points from the lecturer's announcement (October 2026, original in Hebrew), plus what they mean for how we build the repo.

## Deadline

- **Submit the final report and the slides by 15.10.26** in the dedicated Moodle box.
- A late submission (after the semester starts) can bring administrative consequences, such as tuition for an extra semester or a delay in closing the degree. The lecturer cannot help in that case.
- After submitting, **check that the files were uploaded and received correctly.**
- We must also be **ready to present** by this date. The presentation schedule will be announced later.

## Presentation

- **15 minutes in total, split equally** between both members. Keep to the time.
- The grade mainly reflects **understanding and command of the material**, not the slides alone.
- **Speak naturally, in our own words.** Bullet points or headings as cues are fine. **Reading from a script or from the slides brings a significant deduction.**
- Each member presents **a substantial part** and shows they understand it.
- Each member must explain **why**, not only what: which alternatives were considered, how decisions were made, and what the results mean.
- Briefly state **each member's personal contribution**.
- Cover: goal, data, approach, model(s), training and experiments, results, conclusions.
- Slides support the talk and do not replace it. Keep text minimal. Prefer **diagrams, architectures, plots, results and examples.**

## Implications for the Repo

- **Decision log:** for each key decision, record the alternatives we considered and why we chose this one. This is what we must defend orally.
- **Figures from saved runs:** every plot used in the slides or report is generated by code from a saved run (config, seed, metrics). No manual figures.
- **Visual examples:** save sample images (confident correct, deferred, confident wrong / failure cases) for the slides.
- **Architecture / pipeline diagram:** keep one clear diagram of the method (baseline, MC Dropout, Deep Ensembles, defer policy).
- **Contribution log:** keep it current so each member's part is clear for the report and the talk.
- **Shared understanding:** both members must be able to explain every part, so document code and results clearly enough for either of us to present them.
